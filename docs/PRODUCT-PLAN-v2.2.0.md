## 🎯 核心功能规划

### 1. Bug修复与稳定性提升（P0-P2）

#### 1.1 Report JSON控制字符问题（P2）
**问题描述**:
- 生成的报告JSON包含未转义的控制字符
- jq解析失败，但API返回正常
- 文件: `server/routes/report.route.ts` 或 `server/services/report.service.ts`

**解决方案**:
- 在JSON生成前sanitize所有文本内容
- 使用正则表达式移除或转义控制字符
- 添加单元测试验证

**工作量**: 2小时  
**优先级**: P2

#### 1.2 上传功能端到端验证（P1）
**背景**:
- v2.1.0修复了permission middleware的query参数支持
- 需要验证完整上传流程是否正常

**验证步骤**:
1. 创建新项目
2. 上传Excel文件（带projectId query参数）
3. 验证文件解析成功
4. 验证时间线记录

**工作量**: 1小时  
**优先级**: P1

### 2. 知识库AI增强（核心新功能）

#### 2.1 智能知识检索
**功能描述**:
- 用户输入问题，AI从知识库中检索相关内容
- 支持语义检索（不仅仅是关键词匹配）
- 返回Top-K相关文档片段

**技术实现**:
```typescript
// API: POST /api/kb/search
{
  "projectId": "xxx",
  "query": "如何提升抖音视频完播率？",
  "limit": 5
}

// Response:
{
  "results": [
    {
      "documentId": "xxx",
      "fileName": "抖音运营手册.pdf",
      "snippet": "完播率提升的3个关键要素：前3秒吸引力、节奏控制、结尾引导...",
      "relevanceScore": 0.92,
      "pageNumber": 12
    }
  ]
}
```

**技术栈**:
- Claude API (embeddings via prompt)
- 或使用简单的TF-IDF + 关键词匹配
- SQLite FTS5全文检索

**工作量**: 8小时  
**优先级**: P0（核心功能）

#### 2.2 知识库问答助手

## 🤔 技术决策

### 知识库检索方案选择

**方案1: SQLite FTS5全文检索（推荐）**
- 优点: 零额外依赖，性能好，支持中文分词
- 缺点: 语义理解能力弱，需要关键词匹配
- 成本: 免费
- 实施: 8小时

**方案2: Claude API Embeddings**
- 优点: 语义理解强，检索质量高
- 缺点: 需要API调用成本，延迟较高
- 成本: $$（每次检索需要调用API）
- 实施: 12小时

**方案3: 混合方案（FTS5 + Claude重排序）**
- 优点: 结合两者优势
- 缺点: 实现复杂度高
- 成本: $（仅重排序时调用API）
- 实施: 16小时

**最终选择**: 方案1（SQLite FTS5），v2.3.0可以考虑升级到方案3
