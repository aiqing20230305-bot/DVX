## 🎉 版本亮点

### 核心修复：dist/client路由冲突 🐛

v2.4.2修复了v2.4.1测试中发现的P1级别阻塞问题：当dist/client目录存在时，Express的catch-all路由会捕获所有GET请求（包括API），导致API返回HTML而不是JSON。

**问题描述**:
- 当dist/client目录存在时，`app.get('*')`捕获所有请求
- API请求（如GET /api/project）返回HTML页面而不是JSON
- 导致开发环境和E2E测试无法正常执行

**解决方案**:
在catch-all路由中添加API路径检查，跳过`/api/`开头的请求

## 🐛 Bug修复详情

### 问题分析

**现象**:
```bash
$ curl "http://localhost:3001/api/project"
<!DOCTYPE html>
<html lang="zh-CN" class="dark">
...
```

**根本原因**:
在server/index.ts中，静态文件服务的catch-all路由配置不够精确：

```typescript
// Before: 捕获所有请求（包括API）
const clientPath = join(__dirname, '../dist/client')
if (existsSync(clientPath)) {
  app.use(express.static(clientPath))
  app.get('*', (_req, res) => {  // ❌ 捕获所有GET请求
    res.sendFile(join(clientPath, 'index.html'))
  })
}
```

虽然API路由在catch-all之前注册，但由于某种原因（可能是Express路由匹配的内部机制），catch-all仍然捕获了API请求。

**解决方案**:
```typescript
// After: 跳过API路由
const clientPath = join(__dirname, '../dist/client')
if (existsSync(clientPath)) {
  app.use(express.static(clientPath))
  app.get('*', (req, res, next) => {
    // Skip API routes - they should have been handled already
    if (req.path.startsWith('/api/')) {  // ✅ 检查并跳过API路径
      return next()
    }
    res.sendFile(join(clientPath, 'index.html'))
  })
}
```

## 💡 技术说明

### Express路由匹配规则

Express按照路由注册顺序进行匹配：
1. 优先匹配更具体的路由
2. 然后匹配通配符路由
3. 最后匹配catch-all路由

在本修复中：
- API路由（/api/*）先注册
- catch-all路由（*）后注册
- 通过在catch-all中显式检查路径前缀，确保API路由不被捕获

### 向后兼容性

此修复完全向后兼容：
- 生产环境：API和静态文件服务都正常
- 开发环境：API和前端开发服务器都正常
