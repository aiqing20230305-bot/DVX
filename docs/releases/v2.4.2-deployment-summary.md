## 🔧 技术变更

### 修改文件（1个）

**server/index.ts** (+3 lines, -1 line)

**Before (v2.4.1)**:
```typescript
const clientPath = join(__dirname, '../dist/client')
if (existsSync(clientPath)) {
  app.use(express.static(clientPath))
  app.get('*', (_req, res) => {
    res.sendFile(join(clientPath, 'index.html'))
  })
}
```

**After (v2.4.2)**:
```typescript
const clientPath = join(__dirname, '../dist/client')
if (existsSync(clientPath)) {
  app.use(express.static(clientPath))
  // Catch-all route for SPA - only for non-API routes
  app.get('*', (req, res, next) => {
    // Skip API routes - they should have been handled already
    if (req.path.startsWith('/api/')) {
      return next()
    }
    res.sendFile(join(clientPath, 'index.html'))
  })
}
```

**关键变更**:
- ✅ 添加 `req.path.startsWith('/api/')` 检查
- ✅ 如果是API路由，调用 `next()` 继续路由匹配
- ✅ 如果不是API路由，返回SPA的index.html

## 🎓 经验总结

### 做得好的地方 ✅

1. **快速定位问题** - 通过测试日志快速发现路由冲突
2. **最小修改原则** - 只修改4行代码解决问题
3. **完整测试验证** - E2E测试验证所有功能正常
4. **文档同步更新** - 代码、文档同步更新

### 技术洞察 💡

1. **Express路由顺序很重要**
   - API路由先注册
   - catch-all路由后注册
   - 但仍需显式检查路径前缀

2. **显式优于隐式**
   - 明确检查路径前缀比依赖路由顺序更可靠
   - `req.path.startsWith('/api/')` 清晰表达意图

3. **测试驱动修复**
   - 先发现问题（E2E测试）
   - 再定位根因（路由配置）
   - 然后修复验证（再次E2E测试）
