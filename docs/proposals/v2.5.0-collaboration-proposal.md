# v2.5.0 协作功能 - 技术方案

**版本**: v2.5.0  
**预计周期**: 16天  
**目标**: 为"超级洞察"平台添加多人协作能力

---

## 📋 需求概述

### 背景
当前系统为单用户模式，无法支持团队协作场景。随着产品成熟，品牌营销团队、内容策划团队需要多人协作完成内容策略制定。

### 核心功能

1. **用户管理** - 注册、登录、个人资料
2. **项目共享** - 邀请成员、角色管理、权限控制
3. **评论功能** - 对洞察/选题/脚本进行评论讨论
4. **审批流程** - 脚本审批、报告审批

### 用户场景

**场景1：团队协作制定内容策略**
1. 品牌经理创建项目，上传数据
2. 数据分析师查看洞察，添加评论和建议
3. 内容策划师根据洞察生成选题
4. 创意总监审批选题
5. 文案编辑生成脚本
6. 品牌经理审批脚本后导出报告

**场景2：客户服务场景**
1. 代理商创建客户项目
2. 邀请客户查看洞察和选题（只读权限）
3. 客户评论反馈
4. 代理商修改后重新提交审批
5. 客户批准后导出报告

### 新增表

#### 1. users（用户表）

```sql
CREATE TABLE IF NOT EXISTS users (
  id TEXT PRIMARY KEY,                 -- UUID
  email TEXT NOT NULL UNIQUE,          -- 邮箱（登录凭证）
  password_hash TEXT NOT NULL,         -- 密码hash（bcrypt）
  name TEXT NOT NULL,                  -- 用户名
  avatar TEXT,                         -- 头像URL
  role TEXT DEFAULT 'user',            -- 全局角色：admin/user
  status TEXT DEFAULT 'active',        -- 状态：active/inactive/suspended
  email_verified INTEGER DEFAULT 0,    -- 邮箱是否验证
  last_login_at INTEGER,               -- 最后登录时间
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE INDEX idx_users_email ON users(email);
```

#### 2. sessions（会话表）

```sql
CREATE TABLE IF NOT EXISTS sessions (
  id TEXT PRIMARY KEY,                 -- Session ID
  user_id TEXT NOT NULL,               -- 用户ID
  token_hash TEXT NOT NULL,            -- Token hash（用于验证）
  refresh_token_hash TEXT,             -- Refresh token hash
  ip_address TEXT,                     -- 登录IP
  user_agent TEXT,                     -- 浏览器信息
  expires_at INTEGER NOT NULL,         -- 过期时间
  created_at INTEGER NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE INDEX idx_sessions_user_id ON sessions(user_id);
CREATE INDEX idx_sessions_token_hash ON sessions(token_hash);
```

#### 3. project_members（项目成员表）

```sql
CREATE TABLE IF NOT EXISTS project_members (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL,            -- 项目ID
  user_id TEXT NOT NULL,               -- 用户ID
  role TEXT NOT NULL,                  -- 角色：owner/editor/viewer
  permissions TEXT DEFAULT '[]',       -- 自定义权限JSON（可选）
  invited_by TEXT,                     -- 邀请人ID
  joined_at INTEGER NOT NULL,          -- 加入时间
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  UNIQUE(project_id, user_id)
);

CREATE INDEX idx_project_members_project_id ON project_members(project_id);
CREATE INDEX idx_project_members_user_id ON project_members(user_id);
```

**角色权限定义**:
- **owner**: 完全控制权（修改项目、管理成员、删除项目）
- **editor**: 编辑权限（创建/修改洞察、选题、脚本，不能管理成员）
- **viewer**: 只读权限（查看所有内容，添加评论，不能修改）

## 🔐 认证与授权设计

### JWT认证方案

#### Token结构
```typescript
interface JWTPayload {
  userId: string
  email: string
  name: string
  role: string          // 全局角色：admin/user
  iat: number           // 签发时间
  exp: number           // 过期时间（15分钟）
}

interface RefreshTokenPayload {
  userId: string
  sessionId: string
  iat: number
  exp: number           // 过期时间（7天）
}
```

#### Token存储
- **Access Token**: httpOnly cookie（防止XSS）
- **Refresh Token**: httpOnly cookie
- 前端不需要手动管理token

#### Token刷新流程
1. Access Token过期（15分钟）
2. 前端发起API请求，返回401
3. 前端自动调用 `/api/auth/refresh`
4. 使用Refresh Token获取新的Access Token
5. 重试原请求

### 权限中间件

#### 认证中间件（authMiddleware）
```typescript
// 验证JWT token，解析用户信息
export const authMiddleware = (req, res, next) => {
  const token = req.cookies.accessToken
  
  if (!token) {
    return res.status(401).json({ error: 'Unauthorized' })
  }
  
  try {
    const payload = jwt.verify(token, JWT_SECRET)
    req.user = payload  // 注入用户信息到request
    next()
  } catch (error) {
    return res.status(401).json({ error: 'Invalid token' })
  }
}
```

#### 权限检查中间件（requireProjectAccess）
```typescript
// 检查用户是否有项目访问权限
export const requireProjectAccess = (minRole: 'viewer' | 'editor' | 'owner') => {
  return async (req, res, next) => {
    const { projectId } = req.params
    const userId = req.user.userId
    
    // 检查用户是否是项目成员
    const member = await projectMemberRepo.findByProjectAndUser(projectId, userId)
    
    if (!member) {
      return res.status(403).json({ error: 'Access denied' })
    }
    
    // 检查角色权限
    const roleHierarchy = { viewer: 1, editor: 2, owner: 3 }
    if (roleHierarchy[member.role] < roleHierarchy[minRole]) {
      return res.status(403).json({ error: 'Insufficient permissions' })
    }
    
    req.projectMember = member  // 注入成员信息
    next()
  }
}
```

#### 使用示例
```typescript
// 只有owner可以删除项目
router.delete('/:projectId', 
  authMiddleware, 
  requireProjectAccess('owner'), 
  deleteProject
)

// editor和owner可以创建洞察
router.post('/:projectId/insights', 
  authMiddleware, 
  requireProjectAccess('editor'), 
  createInsight
)

// viewer可以查看洞察
router.get('/:projectId/insights', 
  authMiddleware, 
  requireProjectAccess('viewer'), 
  listInsights
)
```

## 🔧 技术实现细节

### 密码加密
使用bcrypt（成本因子12）
```typescript
import bcrypt from 'bcrypt'

const hashPassword = async (password: string) => {
  return await bcrypt.hash(password, 12)
}

const verifyPassword = async (password: string, hash: string) => {
  return await bcrypt.compare(password, hash)
}
```

### JWT实现
使用jsonwebtoken库
```typescript
import jwt from 'jsonwebtoken'

const JWT_SECRET = process.env.JWT_SECRET  // 从环境变量读取
const JWT_EXPIRES_IN = '15m'
const REFRESH_TOKEN_EXPIRES_IN = '7d'

const generateAccessToken = (payload: JWTPayload) => {
  return jwt.sign(payload, JWT_SECRET, { expiresIn: JWT_EXPIRES_IN })
}

const generateRefreshToken = (payload: RefreshTokenPayload) => {
  return jwt.sign(payload, JWT_SECRET, { expiresIn: REFRESH_TOKEN_EXPIRES_IN })
}
```

### 实时评论（WebSocket）
使用Socket.IO实现评论实时更新
```typescript
import { Server } from 'socket.io'

const io = new Server(httpServer, {
  cors: { origin: process.env.CLIENT_URL }
})

io.on('connection', (socket) => {
  // 用户加入项目房间
  socket.on('join-project', (projectId) => {
    socket.join(`project:${projectId}`)
  })
  
  // 新评论广播
  socket.on('new-comment', (comment) => {
    io.to(`project:${comment.project_id}`).emit('comment-added', comment)
  })
})
```

## ⚠️ 风险评估

### 技术风险

**1. SQLite并发性能**
- **风险**: SQLite在高并发场景下性能有限
- **缓解**: 
  - 初期用户量小，SQLite足够
  - 设计时保持数据库抽象层，便于后期迁移
  - 预留PostgreSQL迁移方案

**2. Token安全性**
- **风险**: JWT token泄露、XSS攻击
- **缓解**:
  - 使用httpOnly cookie（防XSS）
  - 短期Access Token（15分钟）
  - HTTPS强制（生产环境）
  - CSP（Content Security Policy）

**3. 实时评论性能**
- **风险**: WebSocket连接过多导致服务器压力
- **缓解**:
  - 按项目分房间，减少广播范围
  - 评论列表分页加载
  - 后期可考虑Redis Pub/Sub

### 业务风险

**1. 权限模型复杂度**
- **风险**: 业务规则变化导致权限模型重构
- **缓解**:
  - RBAC模型简单清晰，易于理解
  - 预留自定义权限字段（JSON）
  - 充分的单元测试覆盖

**2. 审批流程灵活性**
- **风险**: 不同客户审批流程差异大
- **缓解**:
  - 设计通用的多级审批模型
  - 支持"any"/"all"审批规则
  - 后期可扩展更复杂的流程引擎
