### 1. server/index.ts:155 - template possibly undefined

**错误信息**:
```
error TS18048: 'template' is possibly 'undefined'.
```

**问题分析**:
在项目创建路由中，`template`变量在两个不同的if块中定义，导致TypeScript无法确定外部块中`template`是否有值。

**问题代码**:
```typescript
if (templateId) {
  const template = getTemplateById(templateId)
  if (template) {
    // 使用template合并数据
  }
}

const project = projectRepo.create(projectData)

if (templateId) {
  const template = getTemplateById(templateId)  // 重复调用
  if (template && template.knowledgeBase.length > 0) {
    // 创建知识库
  }
  
  // ERROR: template可能undefined
  logRepo.create(project.id, 'create', `创建项目：${project.name}（使用${template.name}模板）`)
} else {
  logRepo.create(project.id, 'create', `创建项目：${project.name}`)
}
```

**修复方案**:
重构代码，将`template`变量提升到函数作用域，避免重复调用`getTemplateById`：

```typescript
let template: any = null

if (templateId) {
  template = getTemplateById(templateId)  // 只调用一次
  
  if (template) {
    // 合并template数据
    projectData = { ... }
  }
}

const project = projectRepo.create(projectData)

// 创建知识库
if (template && template.knowledgeBase.length > 0) {
  for (const kbItem of template.knowledgeBase) {
    kbRepo.create({ ... })
  }
}

// 记录日志（类型安全）
if (template) {
  logRepo.create(project.id, 'create', `创建项目：${project.name}（使用${template.name}模板）`)
} else if (templateId) {
  logRepo.create(project.id, 'create', `创建项目：${project.name}（模板未找到）`)
} else {
  logRepo.create(project.id, 'create', `创建项目：${project.name}`)
}
```

**修复效果**:
- ✅ 消除TypeScript类型错误
- ✅ 避免重复调用API
- ✅ 添加template未找到时的友好提示
- ✅ 防止潜在的运行时错误（访问undefined.name）

### 2. server/routes/video.route.ts:31 - Missing file_type property

**错误信息**:
```
error TS2345: Argument of type '{ project_id: string; filename: string; ... }' is not assignable to parameter of type 'Omit<Upload, "id" | "created_at" | "updated_at">'.
Property 'file_type' is missing in type '{ ... }' but required in type 'Omit<Upload, ...>'.
```

**问题分析**:
`Upload`接口定义中`file_type`字段为必填，类型为`'market_data' | 'product_info' | 'product_features'`。视频上传路由在创建upload记录时遗漏了此字段。

**Upload接口定义**:
```typescript
export interface Upload {
  id: string
  project_id: string
  filename: string
  original_name: string
  mime_type: string
  size: number
  file_type: 'market_data' | 'product_info' | 'product_features'  // 必填
  status: 'uploading' | 'parsing' | 'ready' | 'error'
  parsed_data: string | null
  error_message: string | null
  created_at: number
  updated_at: number
}
```

**问题代码**:
```typescript
const upload = uploadRepo.create({
  project_id: projectId,
  filename: `video-url-${Date.now()}.mp4`,
  original_name: url.split('/').pop()?.split('?')[0] || 'video-from-url.mp4',
  mime_type: 'video/mp4',
  size: 0,
  status: 'parsing',
  parsed_data: null,
  error_message: null,
  // 缺少file_type字段
})
```

**修复方案**:
添加`file_type: 'market_data'`字段：

```typescript
const upload = uploadRepo.create({
  project_id: projectId,
  filename: `video-url-${Date.now()}.mp4`,
  original_name: url.split('/').pop()?.split('?')[0] || 'video-from-url.mp4',
  mime_type: 'video/mp4',
  size: 0,
  file_type: 'market_data',  // 添加此字段
  status: 'parsing',
  parsed_data: null,
  error_message: null,
})
```

**为什么选择market_data**:
- 视频分析通常用于分析竞品、市场趋势、爆款内容
- `product_info`更适合产品说明书、规格文档
- `product_features`更适合产品特性描述
- 视频内容偏向市场洞察，因此归类为`market_data`

**修复效果**:
- ✅ 消除TypeScript类型错误
- ✅ 修复视频上传功能（之前会因缺少字段失败）
- ✅ 数据库记录完整性保证

### 3. server/services/parser/pdf.parser.ts - PDFParse incorrect usage

**错误信息**:
```
error TS1192: Module 'pdf-parse' has no default export.
error TS2339: Property 'parse' does not exist on type 'PDFParse'.
```

**问题分析**:
pdf-parse v2.x使用class-based API，与v1.x的函数式API不同。代码中错误地使用了不存在的导入方式和方法。

**问题代码**:
```typescript
import { PDFParse } from 'pdf-parse'  // ✓ 正确导入（v2.x）

const parser = new PDFParse(buffer)
const pdfData = await parser.parse()  // ✗ parse方法不存在

extractedText = pdfData.text.trim()
pageCount = pdfData.numpages
```

**修复方案**:
使用正确的v2.x API - `getText()`方法：

```typescript
import { PDFParse } from 'pdf-parse'  // 正确导入

const parser = new PDFParse(buffer)
const textResult = await parser.getText()  // 使用getText()方法

extractedText = textResult.text.trim()
pageCount = textResult.pages.length

await parser.destroy()  // 清理资源
```

**API版本差异**:

| 版本 | 导入方式 | 使用方式 | 返回对象 |
|------|---------|---------|---------|
| v1.x | `import pdfParse from 'pdf-parse'` | `const data = await pdfParse(buffer)` | `{ text, numpages }` |
| v2.x | `import { PDFParse } from 'pdf-parse'` | `const parser = new PDFParse(buffer); const result = await parser.getText()` | `{ text, pages[] }` |

**修复效果**:
- ✅ 消除TypeScript类型错误
- ✅ 修复PDF解析功能（之前完全不可用）
- ✅ 正确使用pdf-parse v2.x API
- ✅ 添加资源清理（destroy）
