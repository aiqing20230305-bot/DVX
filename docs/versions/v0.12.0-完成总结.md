**关键逻辑**:
```typescript
// 点击触发
const handleClick = (e: MouseEvent) => {
  const target = e.target as HTMLElement
  activeQuestionnaires.forEach(q => {
    if (q.trigger_rule.type === 'click' && q.trigger_rule.selector) {
      if (target.matches(q.trigger_rule.selector) || target.closest(q.trigger_rule.selector)) {
        triggerQuestionnaire(q.id, q.trigger_rule)
      }
    }
  })
}

// 页面访问触发
useEffect(() => {
  activeQuestionnaires.forEach(q => {
    if (q.trigger_rule.type === 'page' && q.trigger_rule.path === location.pathname) {
      triggerQuestionnaire(q.id, q.trigger_rule)
    }
  })
}, [location.pathname])

// 防重复检查
const checkTriggered = async (questionnaireId: string): Promise<boolean> => {
  // 1. 检查localStorage
  const triggered = localStorage.getItem('questionnaire_triggered')
  const data = triggered ? JSON.parse(triggered) : {}
  if (data[sessionId]?.[questionnaireId]) {
    return true
  }
  
  // 2. 检查服务器
  const response = await fetch(`${API_BASE}/${questionnaireId}/has-triggered?session_id=${sessionId}`)
  const result = await response.json()
  return result.has_triggered
}
```

## 🎯 触发规则实现

### 点击触发（Click Trigger）

**规则格式**:
```json
{
  "type": "click",
  "selector": "button.generate-insights",
  "description": "点击生成洞察按钮后触发"
}
```

**实现原理**:
- 全局监听document click事件
- 检查target.matches(selector)
- 或者target.closest(selector)
- 匹配成功 → 触发问卷

**使用场景**:
- 点击关键功能按钮后
- 完成核心操作后
- 用户交互明确时

### 页面访问触发（Page Visit Trigger）

**规则格式**:
```json
{
  "type": "page",
  "path": "/insights",
  "description": "访问洞察页面时触发"
}
```

**实现原理**:
- 监听location.pathname变化（useEffect）
- 检查path === location.pathname
- 匹配成功 → 触发问卷

**使用场景**:
- 用户首次访问特定页面
- 进入关键流程节点
- 页面停留时收集反馈

## 🔄 工作流程

### 配置触发规则（管理员）

1. 进入问卷编辑器（`/testing/questionnaire/:id/edit`）
2. 选择触发方式："事件触发"
3. 选择规则类型："点击特定元素" 或 "访问特定页面"
4. 输入参数：
   - 点击：CSS选择器（如`button.generate-insights`）
   - 页面：路由路径（如`/insights`）
5. 输入规则描述（如"点击生成洞察按钮后触发"）
6. 保存问卷

### 自动触发流程（用户）

1. 测试用户进入会话详情页
2. 点击"启动追踪"
3. 触发引擎加载所有事件触发问卷
4. 用户正常使用应用：
   - **场景A**: 点击"生成洞察"按钮
     - 触发引擎检测到点击
     - 匹配selector
     - 检查防重复 → 通过
     - 自动弹出问卷
   - **场景B**: 访问`/insights`页面
     - 触发引擎检测到路由变化
     - 匹配path
     - 检查防重复 → 通过
     - 自动弹出问卷
5. 用户填写问卷并提交
6. 触发记录更新（answered=1）

### 查看触发数据（管理员）

1. 进入问卷列表（`/testing/questionnaires`）
2. 事件触发问卷显示"触发"按钮
3. 点击进入触发历史页
4. 查看：
   - 总触发次数
   - 已弹出次数
   - 已回答次数
   - 回答完成率
   - 触发时间线

## 💡 防重复机制

### 设计目标
同一测试会话中，每个问卷最多触发1次，避免骚扰用户。

### 实现方案

#### 1. localStorage存储
```typescript
{
  "session_123": {
    "questionnaire_456": {
      "triggered_at": 1775420000000,
      "answered": false
    }
  }
}
```

#### 2. 服务器存储
```sql
SELECT COUNT(*) FROM questionnaire_triggers
WHERE session_id = ? AND questionnaire_id = ?
```

#### 3. 双重检查
```typescript
const hasTriggered = await checkTriggered(questionnaireId)

if (hasTriggered) {
  // 记录触发但不弹出（shown=0）
  await recordTrigger(questionnaireId, triggerRule, false)
  return
}

// 记录并弹出（shown=1）
await recordTrigger(questionnaireId, triggerRule, true)
onTrigger?.(questionnaireId)
```

### 优势
- **快速响应**: localStorage优先，无网络延迟
- **数据准确**: 服务器备份，刷新页面仍有效
- **可追溯**: 区分"触发"和"实际弹出"

## 🎓 经验总结

### 技术选型

- **Event Delegation** - 全局监听，性能最优
- **localStorage + Server** - 双重防重复，快速且可靠
- **JSON规则** - 灵活扩展，易于解析
- **Hook模式** - React最佳实践，逻辑复用

### 架构设计

- **关注点分离** - Hook负责逻辑，组件负责UI
- **可扩展性** - 规则类型易于新增（duration/sequence）
- **防御性编程** - JSON.parse包裹try-catch
- **性能优化** - localStorage优先，避免频繁API

### 开发效率

- **设计先行** - 完整的设计文档指导开发
- **增量实现** - 先点击和页面，预留扩展
- **测试驱动** - 每个API立即测试
- **MVP原则** - 核心功能先实现，高级功能预留
