### 4. 批量操作性能优化

**需求**: 优化大数据量场景下的批量操作性能

**优化点**:
1. **SQL优化**: 使用事务（Transaction）批量操作
2. **分批处理**: 前端分批发送请求（每批50项）
3. **虚拟滚动**: 列表使用虚拟滚动（react-window）
4. **状态优化**: 使用 `useMemo` 缓存计算结果

**实现要点**:
```typescript
// 后端：使用事务
db.transaction(() => {
  ids.forEach(id => {
    db.prepare('DELETE FROM insights WHERE id = ?').run(id)
  })
})()

// 前端：分批处理
const batchSize = 50
for (let i = 0; i < ids.length; i += batchSize) {
  const batch = ids.slice(i, i + batchSize)
  await batchDelete(batch)
  updateProgress((i + batch.length) / ids.length * 100)
}
```

**优先级**: 中（当前数据量不大）

#### 2. 键盘快捷键

**新增Hook**: `src/hooks/useKeyboardShortcuts.ts`

```typescript
import { useEffect } from 'react'

interface ShortcutConfig {
  key: string
  ctrl?: boolean
  shift?: boolean
  handler: () => void
  description: string
}

export function useKeyboardShortcuts(shortcuts: ShortcutConfig[]) {
  useEffect(() => {
    const handleKeyDown = (e: KeyboardEvent) => {
      // 在输入框中不触发
      const target = e.target as HTMLElement
      if (target.tagName === 'INPUT' || target.tagName === 'TEXTAREA') {
        return
      }

      for (const shortcut of shortcuts) {
        const ctrlPressed = (e.ctrlKey || e.metaKey) === (shortcut.ctrl ?? false)
        const shiftPressed = e.shiftKey === (shortcut.shift ?? false)
        const keyMatch = e.key.toLowerCase() === shortcut.key.toLowerCase()

        if (ctrlPressed && shiftPressed && keyMatch) {
          e.preventDefault()
          shortcut.handler()
          break
        }
      }
    }

    window.addEventListener('keydown', handleKeyDown)
    return () => window.removeEventListener('keydown', handleKeyDown)
  }, [shortcuts])
}
```

**页面集成**: `Insights.tsx`

```typescript

interface ProgressDialogProps {
  open: boolean
  title: string
  progress: number  // 0-1
  total: number
  completed: number
  onCancel?: () => void

export function ProgressDialog({
  open,
  title,
  progress,
  total,
  completed,
  onCancel
}: ProgressDialogProps) {
  if (!open) return null

  return (
    <div className="fixed inset-0 z-50 flex items-center justify-center bg-black/50">
      <div className="bg-slate-800 border border-slate-700 rounded-lg p-6 max-w-md">
        <h3 className="text-lg font-semibold text-slate-100 mb-4">{title}</h3>
        
        <div className="mb-2">
          <div className="flex justify-between text-sm text-slate-400 mb-1">
            <span>{Math.round(progress * 100)}%</span>
            <span>{completed} / {total}</span>
          </div>
          <div className="h-2 bg-slate-700 rounded-full overflow-hidden">
            <div
              className="h-full bg-indigo-600 transition-all duration-300"
              style={{ width: `${progress * 100}%` }}
            />
          </div>
        </div>

        {onCancel && (
          <button
            onClick={onCancel}
            className="mt-4 w-full py-2 bg-slate-700 hover:bg-slate-600 text-slate-300 rounded-lg"
          >
            取消
          </button>
        )}
      </div>
    </div>
  )
}
```

## 💡 设计思考

### 为什么选择这些快捷键？

**Ctrl+A（全选）**: 
- 这是最常用的快捷键之一
- 几乎所有应用都支持
- 用户习惯强

**Delete（删除）**:
- 直观，符合直觉
- 键盘上的专用键
- 仍需确认对话框（安全）

**Esc（取消）**:
- 通用的"退出/取消"操作
- 单手可达
- 符合用户预期

**Ctrl+E（导出）**:
- E = Export
- 不与浏览器快捷键冲突
- 容易记忆

**Ctrl+/（帮助）**:
- 许多应用的标准快捷键
- /符号像问号，暗示"帮助"
- 易于发现

### 为什么不实现Ctrl+Z（撤销）？

**原因**:
1. **复杂度高**: 需要维护操作历史栈
2. **存储成本**: 需要保存撤销前的完整状态
3. **边界情况多**: API调用失败、页面刷新等
4. **收益不明显**: 批量操作有确认对话框，误操作概率低

**结论**: 作为Phase 2功能，v0.17.0不实现

### 为什么导出不需要确认对话框？

**原因**:
1. **非破坏性操作**: 导出不会修改数据
2. **可重复执行**: 用户可以随时再次导出
3. **操作成本低**: 导出失败无严重后果
4. **用户体验**: 减少操作步骤，提升效率

**对比**:
- 删除操作：破坏性，不可逆 → 需要确认
- 导出操作：安全，可重复 → 不需要确认
