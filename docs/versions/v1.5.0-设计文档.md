## 🎯 测试优先级分析

### 高优先级（必须测试）

**1. API层测试**:
- `insight.api.ts` - 洞察API
- `topic.api.ts` - 选题API
- `script.api.ts` - 脚本API
- `upload.api.ts` - 上传API

**原因**: API是核心业务逻辑，错误影响范围大

**2. Hooks测试**:
- `useFileUpload.ts` - 文件上传逻辑
- 其他自定义Hooks

**原因**: Hooks包含复杂状态逻辑，容易出错

### 中优先级（建议测试）

**3. 复杂组件测试**:
- `ProjectDashboard.tsx` - 项目仪表盘
- `DataChartsPanel.tsx` - 数据图表面板

**原因**: 复杂组件包含多个交互逻辑

### 低优先级（可选测试）

**4. 简单组件测试**:
- 已测试的组件增加边界情况
- 纯展示组件

**原因**: 简单组件逻辑简单，风险较低

**测试工具**:

**示例测试**:
```typescript
import { renderHook, act } from '@testing-library/react'
import { useFileUpload } from './useFileUpload'

describe('useFileUpload', () => {
  it('uploads file successfully', async () => {
    const { result } = renderHook(() => useFileUpload())
    
    const file = new File(['content'], 'test.xlsx')
    
    await act(async () => {
      await result.current.upload(file, 'project-1', 'market_data')
    })

    expect(result.current.uploads[0].status).toBe('success')
  })
})
```
