# v0.12.0 事件触发问卷系统 - 设计文档

**版本号**: v0.12.0  
**开始时间**: 2026-04-06  
**功能主题**: 事件触发问卷系统

---

## 📋 产品目标

**核心价值**: 基于用户行为的智能问卷自动触发

让问卷能够根据用户的实际操作行为自动弹出，实现真正的智能化测试反馈收集，减少人工干预。

---

## 🎯 功能需求

### 1. 触发规则类型

#### 点击触发（Click Trigger）
用户点击特定元素后弹出问卷

**示例**:
- 点击"生成洞察"按钮后 → 弹出"洞察生成体验问卷"
- 点击"导出报告"后 → 弹出"报告导出满意度问卷"

**规则格式**:
```json
{
  "type": "click",
  "selector": "#generate-insights-btn",
  "description": "点击生成洞察按钮"
}
```

#### 页面访问触发（Page Visit Trigger）
用户访问特定页面后弹出问卷

**示例**:
- 访问`/insights`页面 → 弹出"洞察页面使用体验问卷"
- 访问`/report`页面 → 弹出"报告功能反馈问卷"

**规则格式**:
```json
{
  "type": "page",
  "path": "/insights",
  "description": "访问洞察页面"
}
```

#### 停留时长触发（Duration Trigger）
用户在某页面停留超过N秒后弹出问卷

**示例**:
- 在`/workbench`停留超过30秒 → 弹出"工作台体验问卷"

**规则格式**:
```json
{
  "type": "duration",
  "path": "/workbench",
  "duration": 30,
  "description": "工作台停留30秒"
}
```

#### 操作序列触发（Sequence Trigger）
用户完成一系列操作后弹出问卷

**示例**:
- 上传文件 → 生成洞察 → 创建选题 → 弹出"完整流程体验问卷"

**规则格式**:
```json
{
  "type": "sequence",
  "steps": ["upload", "insights", "topics"],
  "description": "完成内容创作流程"
}
```

### 2. 防重复触发机制

#### 同一会话内防重复
同一测试会话中，每个问卷最多触发1次

#### 冷却时间
同一问卷触发后，N分钟内不再触发

#### 已提交不再触发
用户已提交过该问卷，不再触发

### 3. 触发历史记录

记录每次触发事件：
- 触发时间
- 触发规则
- 是否弹出（可能因防重复而未弹出）
- 用户是否回答
- 答案ID

### 4. 管理界面

#### 规则配置
- 在问卷编辑器中配置触发规则
- 可视化规则编辑器（下拉选择 + 参数输入）
- 规则测试功能

#### 触发历史
- 查看某问卷的触发历史
- 触发成功率统计
- 回答完成率统计

## 🗄️ 数据库设计

### 新增表：questionnaire_triggers

```sql
CREATE TABLE IF NOT EXISTS questionnaire_triggers (
  id TEXT PRIMARY KEY,
  session_id TEXT NOT NULL,
  questionnaire_id TEXT NOT NULL,
  trigger_rule TEXT NOT NULL,          -- JSON格式的触发规则
  triggered_at INTEGER NOT NULL,       -- 触发时间戳
  shown INTEGER NOT NULL DEFAULT 1,    -- 是否实际弹出 (0=未弹出, 1=已弹出)
  answered INTEGER NOT NULL DEFAULT 0, -- 是否已回答 (0=未回答, 1=已回答)
  response_id TEXT,                    -- 关联的feedback_response.id
  created_at INTEGER NOT NULL,
  FOREIGN KEY (session_id) REFERENCES test_sessions(id) ON DELETE CASCADE,
  FOREIGN KEY (questionnaire_id) REFERENCES questionnaires(id) ON DELETE CASCADE
);
```

**字段说明**:
- `trigger_rule`: JSON格式，记录触发规则的详细信息
- `shown`: 区分"触发"和"实际弹出"（可能因防重复而未弹出）
- `answered`: 用户是否完成回答
- `response_id`: 关联到feedback_responses，便于追踪

## 🔄 工作流程

### 管理员配置触发规则

1. 进入问卷编辑器（`/testing/questionnaire/:id/edit`）
2. 在"触发方式"选择"事件触发"
3. 配置触发规则：
   - 规则类型：点击/页面/停留/序列
   - 规则参数：选择器/路径/时长/步骤
4. 保存问卷

### 测试用户触发问卷

1. 测试用户正常使用应用
2. 触发引擎监听用户行为
3. 匹配到触发条件：
   - 检查防重复规则
   - 如果通过 → 自动弹出问卷
   - 如果未通过 → 记录触发但不弹出
4. 记录触发事件到数据库

### 用户回答问卷

1. 问卷弹窗自动显示
2. 用户作答并提交
3. 更新触发记录（answered=1, response_id=xxx）

### 管理员查看触发数据

1. 进入问卷统计页
2. 查看触发历史：
   - 触发次数
   - 弹出次数
   - 回答次数
   - 回答率
3. 分析问卷触发效果

## ⚡ 防重复机制

### 实现方案

**localStorage存储**:
```typescript
const TRIGGERED_KEY = 'questionnaire_triggered'

// 存储格式
{
  "session_123": {
    "questionnaire_456": {
      "triggered_at": 1775419600000,
      "answered": false
    }
  }
}
```

**检查逻辑**:
```typescript
function shouldTrigger(sessionId: string, questionnaireId: string): boolean {
  const triggered = localStorage.getItem(TRIGGERED_KEY)
  const data = JSON.parse(triggered || '{}')
  
  // 已触发过
  if (data[sessionId]?.[questionnaireId]) {
    return false
  }
  
  return true
}
```

**记录触发**:
```typescript
function markTriggered(sessionId: string, questionnaireId: string) {
  const triggered = localStorage.getItem(TRIGGERED_KEY)
  const data = JSON.parse(triggered || '{}')
  
  if (!data[sessionId]) {
    data[sessionId] = {}
  }
  
  data[sessionId][questionnaireId] = {
    triggered_at: Date.now(),
    answered: false
  }
  
  localStorage.setItem(TRIGGERED_KEY, JSON.stringify(data))
}
```
