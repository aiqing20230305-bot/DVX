**新增端点**:

**已存在端点**（验证功能正常）:
- `DELETE /api/insight/batch` - 批量删除洞察

- `DELETE /api/script/batch` - 批量删除脚本
- `PATCH /api/topic/batch-priority` - 批量调整优先级

**关键修复**:
- **路由顺序问题**: 发现并修复了 Express 路由匹配问题
  - 问题：`PATCH /batch` 被 `PATCH /:id` 误匹配，导致批量更新失败
  - 原因：Express 按注册顺序匹配路由，`/:id` 会匹配 `/batch`（id="batch"）
  - 解决：将所有批量路由（`/batch`, `/batch-priority`）移到参数化路由（`/:id`）之前
  - 文件：`server/routes/topic.route.ts`

**实现细节**:
```typescript
// topic.repo.ts - 批量更新实现
updateBatch(ids: string[], data: { selected?: boolean }): void {
  const db = getDb()
  const now = Date.now()
  if (ids.length === 0) return

  const placeholders = ids.map(() => '?').join(',')
  const selected = data.selected !== undefined ? (data.selected ? 1 : 0) : undefined

  if (selected !== undefined) {
    db.prepare(`UPDATE topics SET selected = ?, updated_at = ? WHERE id IN (${placeholders})`)
      .run(selected, now, ...ids)
  }
}
```

batchDelete: async (ids) => {

    method: 'DELETE',
    body: JSON.stringify({ ids })

## 🎓 经验总结

### 1. Express 路由顺序的重要性

**教训**:
- Express 路由匹配是按注册顺序进行的
- 参数化路由（如 `/:id`）会匹配任何路径
- 明确路由必须在参数化路由之前注册

**最佳实践**:
```typescript
// ✅ 正确：明确路由在前
router.patch('/batch', ...)
router.patch('/batch-priority', ...)
router.patch('/:id', ...)  // 放最后

// ❌ 错误：参数化路由在前
router.patch('/:id', ...)
router.patch('/batch', ...)  // 永远不会被匹配
```

**预防措施**:
- 添加注释说明路由顺序要求
- 使用路由分组（Express Router）
- 编写单元测试验证路由匹配

### 2. 调试技巧

**问题定位流程**:
1. **现象观察**: 返回格式不符预期
2. **日志调试**: 添加console.log跟踪执行路径
3. **工具验证**: 使用curl直接测试API
4. **代码审查**: 检查路由注册顺序
5. **根因分析**: Express路由匹配机制
6. **修复验证**: 重新测试确认修复

**经验**:
- 先验证API响应，再检查前端调用
- 使用curl等工具隔离变量
- 添加临时日志快速定位问题
- 修复后清理临时代码

### 3. 组件化开发

**收益**:
- 代码复用：BatchToolbar在3个页面复用
